🏢 BassSaasApp 통합 플랫폼 운영 매뉴얼

플랫폼 아키텍처: 객체 지향 마이크로 SaaS (App-as-an-Object) · 버전 1.0.0

1. 플랫폼 아키텍처 원리 (Two-Tier Object Model)

BassSaasApp은 17개에서 50~100개 앱으로 확장 시 발생하는 게이트웨이 모놀리스 병목을 해결하기 위해 개발되었습니다.
  • 계층 1: 시스템 레벨 객체화 (BaseSaaSApp)
    각 앱은 app.py에 정의된 파이썬 클래스 인스턴스 1개로 존재합니다. 게이트웨이는 apps/ 디렉터리를 스캔하여 라우터 마운트, 정적 파일 서빙, 헬스체크 및 서브도메인을 100% 자동 연결합니다. 게이트웨이 코드는 단 한 줄도 수정하지 않습니다.
  • 계층 2: 도메인 레벨 객체화 (Kernel Obj)
    모든 앱의 비즈니스 엔티티는 스스로 저장(save()), 조회(get(), find()), 로깅(log())을 수행하는 스키마리스 WAL 저장소를 공유합니다. 필드가 새로 추가되어도 DB 마이그레이션이 필요 없습니다.

2. 새 앱 추가 절차 (Zero-Touch)

  1. 터미널에서 스캐폴더 명령어 1회 실행: 
    py -3.14 scripts/create_app.py --id myapp --name "내 신규 서비스" --icon ⚡ --category business
  2. apps/myapp/backend/domain.py에 도메인 객체 및 행동 메서드 작성.
  3. 서버를 재시작하면 게이트웨이가 새 앱을 즉시 감지하여 포털에 자동 등록합니다.

3. 결함 격리 (Fault Isolation & Sandbox)

100개 앱 중 특정 앱의 코드에 문법 오류나 런타임 예외가 발생하더라도, 게이트웨이는 해당 앱만 일시 격리(ISOLATED) 상태로 전환하고 503 에러 안내 페이지를 서빙합니다. 나머지 99개 앱은 아무런 지장 없이 100% 정상 가동됩니다.

4. 표준 에러 및 알림 배너 체계

배너 색상도메인 레벨HTTP 코드의미 및 용도
✅ 녹색success200정상 처리 완료 (결제 성공, 입실 완료 등)
⚠️ 황색warning400 / 409중복 실행 방지, 이미 처리된 상태 안내
⚖️ 주황색diff422입력값과 청구 금액의 차액 발생 안내
❌ 적색error404 / 500엔티티 부재, 권한 부족, 시스템/격리 오류

5. 관리자 계정 및 권한

  • 본사 총괄 최고관리자: 아이디 admin / 비밀번호 1212 (superadmin)
  • 모든 데이터 생성/수정/삭제 행위는 actor와 함께 중앙 변경 이력(Timeline)에 자동 영구 보존됩니다.

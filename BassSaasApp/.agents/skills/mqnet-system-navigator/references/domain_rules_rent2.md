# MQnet Domain Rules & Business Logic (Rent2 Core)

`apps/rent2`는 실제 부동산 임대차 현장의 실무 규칙을 100% 정합하게 반영한 스마트 모바일 자산관리 엔진입니다.

---

## 1. 선납 / 후불 및 체납 판정 원칙 (Domain Logic Soundness)

### 1.1. 후불 입주월 비과세 / 익월 청구 원칙
- **현실 비즈니스 규칙**: 월세가 "후불"인 경우, 해당 월에 입주하면 해당 월에는 당월 청구가 발생하지 않으며, 다음 달에 전월 사용료가 청구됩니다.
- **가짜 체납(Ghost Overdue) 원천 차단**:
  - 입주월 당월을 미납(체납)으로 오판단하여 알림을 발송하거나 빨간색 경고를 표시하는 왜곡을 원천 차단합니다.
  - 전입일(`move_in`) 이전 날짜는 절대 청구 대상에 포함되지 않습니다.

### 1.2. 선납 확장 및 다개월 분할
- 선납 계약의 경우 입주 당월 청구가 즉시 발생하며, 계약 만료일(`expiry`) 범위 내에서만 청구 스케줄이 생성됩니다.
- 한 번에 여러 달을 선납하거나 분할 입금하는 경우, 결제 금액이 청구 월 단위로 정확히 쪼개져 반영됩니다.

---

## 2. 스마트 문자 파싱 및 FIFO(선입선출) 자동 수납 엔진

### 2.1. 은행/카드 입금 문자 지능형 파싱 (`apps/rent2/backend/domain/parser.py`)
- 은행 입금 통지 문자(신한, 국민, 농협, 카카오뱅크, 토스 등)를 그대로 복사하여 붙여넣으면, 호실(예: `201호`), 입금자명(`홍길동`), 금액(`500,000원`), 일시를 정규식 및 패턴 매칭으로 자동 추출합니다.

### 2.2. FIFO(선입선출) 순차 상계 원칙
- 특정 호실에 입금이 들어오면, **가장 오래된 미납월(Oldest Unpaid Month)부터 순차적으로 완납 처리**합니다.
- 예: 8월 미납 50만 원, 9월 미납 50만 원인 상태에서 70만 원이 입금된 경우:
  1. 8월 분: 50만 원 완납 처리 (잔여 미납 0원)
  2. 9월 분: 남은 20만 원 부분 납부 처리 (잔여 미납 30만 원)

### 2.3. 멱등성 및 중복 입금 차단 (Idempotency Protection)
- 동일한 입금 내역(동일 호실, 동일 입금자, 동일 금액, 동일 납부월)이 이중으로 등록되지 않도록 백엔드에서 원천 차단합니다.
- 중복 시도 시 HTTP 200 반환과 함께 `success: False`, 명확한 사유(`⚠️ [중복 입금 오류] 이미 처리된 내역입니다`)를 반환합니다.

---

## 3. 부가세(VAT) 처리 표준 (`apps/rent2/backend/domain/vat.py`)
- 일반 주거용 원룸: 면세 (VAT 없음)
- 상가 / 사무실 / 부가세 별도 계약:
  - 공급가액(월세) + 10% VAT 자동 계산
  - 세금계산서 발행 대상 플래그 및 사업자등록번호 검증
- 수납 처리 시 부가세 포함 금액과 공급가액을 명확히 분리 기록하여 회계 왜곡을 방지합니다.

---

## 4. 단일 진입점 정규화 (Single Source of Truth)
- **지점 ID 에일리어스 (`normalize_branch_id`)**:
  - `imsi`, `main`, `1`, `sinbi` 등 다양한 입력값을 도메인 서비스 진입점에서 단일 Canonical ID로 1회 정규화하여 하위 레이어의 불일치 위험을 차단합니다.
- **금액 기본값 (Fallback Guard)**:
  - 데이터 누락이나 빈 문자열 입력 시 `0` 또는 계약 기본값으로 안전하게 치환하여 계산 오류(`NaN` 또는 `TypeError`)를 방지합니다.

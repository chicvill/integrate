# MQnet Development & Resilient UX Standards

MQnet 플랫폼은 사용자에게 최고의 시각적/기능적 경험을 제공하고 시스템 신뢰성을 보장하기 위해 엄격한 개발 및 UX 표준을 강제합니다.

---

## 1. 프론트엔드 아키텍처: Zero-Build 번들리스 원칙
- **순수 ES Module & Vanilla JS**:
  - Webpack, Vite, Babel 등 무거운 빌드 단계 없이 브라우저 표준 `import`/`export`를 사용합니다.
  - 개발자가 코드를 수정하고 저장하면 브라우저 새로고침(F5) 즉시 결과가 반영됩니다.
- **캐시 고착 원천 방지 (`NoCacheStaticFiles`)**:
  - 게이트웨이 및 백엔드 정적 서빙 시 `Cache-Control: no-cache, no-store, must-revalidate` 헤더를 강제합니다.
  - 스크립트 호출 시 버전 파라미터(`?v=X.X`)를 부착하여 구버전 스크립트 충돌을 방지합니다.

---

## 2. 사용자 및 시스템 안내 표준 (Resilient Alert Banner UX)

### 2.1. 투박한 브라우저 `alert()` 전면 퇴출
- 사용자 경험을 저해하는 시스템 팝업 `alert()` 대신, 화면 상단에 일관되게 표시되는 비동기 배너(`updateAppAlert` 또는 `showTopToast`)를 사용합니다.

### 2.2. 맥락별 4색 안내 배너 체계
| 색상 / 유형 | 사용 맥락 (Context) | 예시 메시지 |
| :--- | :--- | :--- |
| ⚠️ **황색 (Warning / Info)** | 미납 내역 없음, 전액 완납 완료, 불필요한 중복 실행 방지 | `"201호는 현재 미납된 임대료가 없습니다."` |
| ⚖️ **주황색 (Diff / Mismatch)** | 입력 금액과 청구 금액의 차액 발생 (부분 납부 또는 과오납) | `"청구액 500,000원 중 300,000원만 입금되어 잔여 200,000원이 미납으로 유지됩니다."` |
| ❌ **적색 (Error / Failure)** | 서버 오류, 유효하지 않은 데이터, 네트워크 단절 | `"서버와의 통신이 실패했습니다. (사유: DB 접근 권한 오류)"` |
| ✅ **녹색 (Success)** | 정상 수납 완료, 계약 갱신 완료, 전산 반영 성공 | `"수납 처리가 정상 완료되었습니다. 영수증이 클립보드에 복사되었습니다."` |

## 3. 회복탄력성 (Resilience) 및 안전 표준

### 3.1. 무음 에러 삼킴(Silent Failure) 절대 금지
- `try ... catch (err)` 구문에서 단순히 `console.error`만 찍고 사용자 인터페이스가 멈추는 행위를 엄격히 금지합니다.
- 반드시 사용자에게 실패 원인과 후속 대처법을 적색 배너로 명확히 고지해야 합니다.

### 3.2. 이중 클릭 방지 & 로딩 복원 (Debounce & State Restoration)
- 전산 처리 버튼(예: `수납 확정`, `계약 등록`) 클릭 시 즉시 `btn.disabled = true` 처리 및 버튼 텍스트를 `처리 중... ⏳`로 변경합니다.
- 처리가 완료되거나 중간에 에러가 발생한 경우, `finally` 블록에서 버튼 활성화 및 원래 텍스트를 즉시 복원하여 사용자가 재시도할 수 있도록 보장합니다.

---

## 4. 공식 운영 매뉴얼 (`manual.html`) 표준
- 모든 SaaS 앱과 템플릿의 프론트엔드 루트에는 단독 실행 가능한 `manual.html`이 반드시 포함되어야 합니다.
- 상단 헤더에 `[🖨️ 매뉴얼 인쇄 / PDF 저장]` 버튼을 필수로 배치합니다.
- `@media print` 스타일을 적용하여 종이(A4) 출력 시 불필요한 배경/버튼을 숨기고 고대비 흑백으로 선명하게 인쇄되도록 합니다.

🏛️ 1. 핵심 설계 철학: 듀얼 모드(Dual-Mode) 아키텍처

MQnet의 모든 앱은 소스 코드 수정 없이 환경변수(RUN_MODE)에 따라 중앙 통합 SaaS와 완전 자립형 단독 패키지로 자동 전환됩니다.

┌─────────────────────────────────────────────────────────────────────────────┐ │ 단일 모노레포 코드베이스 (Mono-Repo) │ └──────────────────────────────────────┬──────────────────────────────────────┘ │ ┌──────────────────────────┴──────────────────────────┐ ▼ ▼ 🏢 [모드 1: 중앙 멀티테넌트 SaaS] 📦 [모드 2: 단독 분리형 Standalone] • 본사 포털(34.31.10.12)에 통합 마운트 • 고객 전용 구글 클라우드 VM 또는 관리실 PC • 다중 매장/건물(Multi-Branch) 통합 관제 • 단독 실행 (80 포트 단독 점유) • 중앙 DB (integrat.db) 공유 • 로컬 전용 DB (./data/app.db) 완벽 격리 • 본사 최고관리자가 원격 일괄 패치 • 외부 인터넷 없는 100% 사내 폐쇄망 지원

☁️ 모드 1: 중앙 SaaS 모드

• 단일 서버에서 다수 매장 실시간 원격 관제
• admin/1212: 본사 지점/수납 센터 (/branches.html)
• 점주 실장: 소속 지점 실시간 관제 (?branch=...)
• 자동 암호화 볼트(.env.encrypted)로 비밀키 완전 보호

🏢 모드 2: 단독 분리형 (Standalone)

• 개인정보 유출을 극도로 꺼리는 개인 건물주를 위한 사내 인트라넷 폐쇄망 지원
• 관리실 윈도우 PC 바탕화면에서 START.bat 더블클릭만으로 즉시 구동
• 데이터(./data/rent.db)는 고객 PC에만 영구 보존되어 클라우드 유출 0%
• UPDATE.bat 더블클릭으로 기존 DB 보존하며 10초 만에 새 버전 갱신

🔄 2. 전체 앱 라이프사이클 표준 (개발-배포-운영-업그레이드)

단계 실행 도구 & 명령어 핵심 규칙 및 표준 동작 원리
1. 기획 & 생성 py scripts/create_app.py --id {app} 표준 템플릿(saas-template)을 복제하여 3초 만에 프론트/백엔드/도커 일체 자동 구성
2. 로컬 개발 py -m uvicorn apps.{app}.backend.main:app 번들리스 원칙: 번들링 빌드 없이 순수 Vanilla JS로 작성하여 브라우저 F5 즉시 반영
3. 정합성 & 검증 py -m py_compile ... 가짜 체납 방어, 에러 배너(showTopToast) UX 준수, 버튼 이중 클릭 방지(disabled)
4. 번들 빌드 py scripts/build_{app}_bundle.py 독립 실행용 단일 bundle.js 생성 및 캐시 버스팅 쿼리(?v=X.X) 적용
5. 서버 배포 powershell -File scripts/sync_{app}_patch.ps1 데이터 선(先)백업: 서버의 최신 integrat.db를 먼저 백업 후 무중단 컨테이너 핫패치
6. 단독 추출 py scripts/export_app.py --app {app} --zip 고객 납품용 1-클릭 실행 파일(START.bat, UPDATE.bat) 및 ZIP 배포팩 자동 생성
7. 운영 & 모니터링 StorageMonitorDaemon 자동 가동 SQLite WAL 파일 및 스토리지 사용량 실시간 감시, 메모리 자동 압축 및 OOM 방지

⚙️ 4. SaaS 템플릿 제약 사항 및 기술적 대응 방안

⚠️ 구글 무료 티어 (RAM 1GB) 메모리 한계

문제: 컨테이너가 누적되면 OOM(Out of Memory) 프로세스 강제 종료 발생 위험.
해결: 가변 주기 백그라운드 모니터링 데몬 도입, 비동기 ThreadPoolExecutor 최적화, 메모리 과다 앱은 export_app.py로 타 서버 즉시 분리.

🔒 SQLite 동시 쓰기 락 (Lock)

문제: 동시 입금 처리 시 database is locked 오류 가능성.
해결: WAL(Write-Ahead Logging) 모드 기본 적용, 트랜잭션 범위를 0.01초 내로 극소화, 대규모 사업장은 DB_URL 환경변수에 PostgreSQL 주소만 넣으면 0초 마이그레이션.
